# AgentShield Lab — Rule-based AI prompt security prototype

[![AgentShield Demo](https://github.com/mchandra452/CyberMahi/actions/workflows/agentshield-demo.yml/badge.svg)](https://github.com/mchandra452/CyberMahi/actions/workflows/agentshield-demo.yml)

AgentShield is a **local Python demonstration of static prompt-pattern detection**, not a production AI-agent firewall. It checks text against configured phrases, applies rule-defined risk labels, emits redacted alerts and generates analyst-style reports. It **does not call an LLM, enforce agent tool permissions or validate actual model behaviour**.

## Quick start

```bash
git clone https://github.com/mchandra452/CyberMahi.git
cd CyberMahi/projects/AgentShield-Lab
python main.py --demo --report
python -m unittest discover -s tests
```

Other commands:

```bash
python main.py --file demo_prompts.txt --report
python main.py --min-risk-score 70
python -m pip install -r requirements.txt
streamlit run dashboard.py
```

The CLI and unit tests use Python's standard library. Streamlit is optional.

The demo scans four synthetic prompts and shows each matching rule and its risk score. The default alert log at `logs/generated_alerts.jsonl` accumulates matches across runs. Each run with `--report` writes a fresh Markdown summary to `reports/demo_report.md` and JSON and CSV summaries to `logs/reports/`.

## Implemented components

| Component | Implementation |
| --- | --- |
| `main.py` | Demo, file-based and interactive prompt analysis, structured alert logging and summary export |
| `detection/detection_rules.json` | Human-readable matching patterns, static severities and risk scores |
| `detection/risk_engine.py` | Aggregation of alert counts and highest risk labels |
| `report_writer.py` | Local Markdown analyst summary |
| `dashboard.py` | Optional Streamlit interface |
| `tests/test_main.py` | Known benign/suspicious phrases, CLI privacy regression tests |

The previous nested `AgentShield-Lab/AgentShield-Lab/` prototype was redundant and removed from the current working tree. Its historical content remains available in Git history. Only the top-level CLI is maintained.

## What the alerts mean

The detector lowercases and normalises whitespace before simple substring matching. It **cannot reliably detect paraphrased attacks**, encoded prompts, malicious tool results, multi-turn exploitation or harmful intent. False positives and false negatives are expected. A result of zero alerts means no configured pattern matched; **it is not a safety guarantee**. Scores are rule-defined labels, not probabilities of attack.

## Privacy and operational limits

Emitted alerts use `input_sample: "[REDACTED]"` and include input length rather than original prompt content. The file-scan and demo modes no longer echo full prompts. The matched patterns themselves are rule-defined strings. Inputs still exist in process memory, source files, terminal input and an optional Streamlit session; the tool is **not** suitable for confidential data. Logs generated by older revisions may contain raw prompts and require independent review/deletion. Git ignores newly generated local alert logs.

Nothing here is integrated with live Sentinel/Splunk, a real agent workflow or a production incident pipeline. The project does not provide a secure sandbox, tool-call authorization or calibrated detection quality.

See [evaluation and next experiments](docs/evaluation.md) and the example [SIEM queries](docs/soc_kql_splunk_queries.md).

## Responsible use

Use synthetic inputs in an authorised local lab only. Never treat rule matches as proof of a malicious actor, or absence of matches as proof of security.
